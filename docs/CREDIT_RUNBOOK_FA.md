# راهنمای عملیات حساب اعتباری

## اتصال

از ریشهٔ مخزن و محیط Python نصب‌شده، `wallex-credit setup --secrets .secrets/credit.json` را اجرا کنید. کلید حساب اعتباری و Client ID همان حساب به‌صورت مخفی خوانده و در فایل محلی با دسترسی ۰۶۰۰ ذخیره می‌شوند. این پوشه در Git نادیده گرفته می‌شود. به‌جای فایل می‌توان `WALLEX_API_KEY` و `WALLEX_SUBACCOUNT_CLIENT_ID` را از مدیر اسرار به محیط پردازش داد؛ کلید را در command line، README، اسکرین‌شات یا چت نگذارید. فقط دسترسی مشاهده و معامله لازم است؛ برداشت لازم نیست.

`wallex-credit doctor --secrets .secrets/credit.json` هیچ سفارش یا تنظیمی را تغییر نمی‌دهد. کلید اختصاصی اعتبار و هدر `sub-account-client-id` روی تمام درخواست‌های خصوصی ارسال می‌شوند. سرویس‌های احراز:

- `GET /sub-accounts`: Client ID دقیق، نوع prop، فعال و غیرمعلق.
- `GET /v1/prop/user/packages/active`: بسته ۱۸۳، ارز TMN، وضعیت active/open، انقضای معتبر و عدم اتصال کیف‌پول اصلی. شکل ناشناختهٔ پاسخ پذیرفته نمی‌شود.
- `GET /v1/account/balances-detail`: موجودی کیف‌پول اعتباری؛ مسیر موجودی حساب اصلی استفاده نمی‌شود.
- `GET /v1/account/fee`: Maker/Taker نماد انتخابی پیش از ورود؛ مقدار بالاتر از ذخیرهٔ کارمزد تنظیم‌شده مانع ورود است.

مسیرهای سفارش `POST /v1/account/orders` و استعلام/لغو `GET/DELETE /v1/account/orders/{client_id}` هستند. تنها LIMIT پشتیبانی می‌شود؛ برخی بازارها از جمله PUMP سفارش MARKET را نمی‌پذیرند. قیمت محدود قابل اجرا، تضمین پرشدن نیست. شناسه شامل حروف، رقم و underscore است.

## پیش از اجرا

۱. زمان دقیق پایان معاملات را در `config/credit-research.json`، فیلد `trading_end_at` با منطقه زمانی ثبت کنید. این زمان از انقضای اعتبار فراتر نمی‌رود. مهلت ارسال کد، زمان پایان معامله نیست.

۲. آزمون سایه را با همین پروفایل انجام دهید. تغییر به AI یا تغییر اندازهٔ سرمایه، نسخهٔ متفاوتی ایجاد می‌کند؛ نتایج قدیمی را به نسخهٔ متفاوت نسبت ندهید.

۳. `wallex-credit freeze` اثرانگشت همان سورس و تنظیمات را ایجاد می‌کند. نسخه‌ای را تحویل دهید که واقعاً اجرا خواهد شد؛ بعد از تحویل کد را تغییر ندهید. هر تغییری قبل از تحویل نیازمند بررسی و freeze تازه است.

۴. `wallex-credit run --secrets .secrets/credit.json --db results/private/credit-live.db --cycles 0` پردازش مستمر است. فقط یک پردازش و یک DB برای حساب استفاده کنید. نمونهٔ سرویس Linux در `deploy/wallex-credit.service` است. اجرای یک چرخه و خاموش‌کردن ربات زنده پشتیبانی نمی‌شود.

## بازیابی و خطا

- DB را روی فضای پایدار نگه دارید و برای همان حساب از همان فایل استفاده کنید. تغییر پروفایل/حساب با وضعیت قدیمی مسدود می‌شود. قفل DB مانع اجرای هم‌زمان دو پردازش روی همان فایل است؛ فایل دیگر برای همان حساب نسازید.
- POST بدون نتیجه، در حالت pending باقی می‌ماند. حتی اگر استعلام «پیدا نشد» برگرداند، سفارش جدید خودکار ساخته نمی‌شود. ابتدا با همان شناسه و از طریق والکس وضعیت را قطعی کنید؛ حذف pending برای رفع ظاهری خطا ممنوع است. این رفتار ممکن است نیازمند بررسی پشتیبانی باشد.
- سفارش باز بعد از ۲۰ ثانیه برای لغو درخواست می‌گیرد؛ تا تأیید نهایی، سفارش بعدی ارسال نمی‌شود. دارایی نیمه‌خریدشده ممکن است در این فاصله در معرض نوسان باشد.
- پس از سفارش نهایی، مقدار و وجه واقعی کیف‌پول تطبیق می‌یابند. مقدار نیمه‌فروخته‌شده حفظ و دلیل خروج تا پایان فروش باقی می‌ماند. اگر عمق کم باشد، خروج تکه‌تکه ادامه پیدا می‌کند؛ دارایی کمتر از حداقل سفارش یا نامجازشدن بازار نیازمند رسیدگی و گزارش صریح است.
- خطای API یا داده موجب HOLD، ثبت خطا و ادامهٔ پایش می‌شود. اختلال شبکه می‌تواند خروج را به تأخیر بیندازد؛ حد ضرر، سفارش توقف میزبانی‌شده در صرافی نیست.
- زمان پایان از پنج دقیقه قبل وارد حالت تسویه می‌شود. خاموشی سرور، صف یا حداقل سفارش می‌توانند مانع تسویهٔ کامل شوند؛ صفر بودن دارایی را از وضعیت واقعی تأیید کنید.

## مشاهده و ارائهٔ دلیل هر معامله

```sh
wallex-credit status --db results/private/credit-live.db
wallex-credit export --db results/private/credit-live.db > results/private/live-events.json
wallex-agent verify-log results/private/credit-live.db
```

رویدادها snapshot بازار، تصمیم ورود، هزینه، عمق و زمان دریافت، دلیل خروج حفاظتی، شناسهٔ سفارش و پاسخ نهایی تطبیق‌یافته را به هم متصل می‌کنند. پاسخ خام حساب و کلید چاپ نمی‌شوند. پیش از تحویل عمومی، شناسه‌های حساب/سفارش و اطلاعات شخصی لاگ را بازبینی کنید؛ اگر لاگ را حذف/تغییر می‌دهید، نسخهٔ اصلی را برای بررسی محرمانه حفظ کنید و فایل ویرایش‌شده را زنجیرهٔ اصلی معرفی نکنید.

## محدودیت عملی باقی‌مانده

هیچ کلید خصوصی در این محیط دریافت نشده و اتصال احرازشده، نرخ API خصوصی و اجرای سفارش واقعی آزمایش نشده‌اند. آزمون‌های چرخهٔ سفارش با سرور ساختگی انجام شده‌اند. دادهٔ عمومی سایه در زمان آزمون، مرجع ناقص داشت. آماده‌بودن کد به معنی تأیید سوددهی یا اجرای زنده نیست.
